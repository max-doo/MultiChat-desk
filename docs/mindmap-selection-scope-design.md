# 思维导图选区交互重设计

## 结论

默认行为是按整篇文档生成。选区不是用户需要选择或确认的范围，而是文档里发生选择动作后自动产生的一次性上下文。新交互不展示任何范围选择控件，也不占用面板顶部；只要存在选区，面板就用同一套固定高度文本区展示原文，内容超出时在该文本区内滚动。

可交互原型见 `docs/mindmap-selection-scope-prototype.html`。页面左下角可以在“文档中有选区”和“默认全文”两个状态之间切换；直接打开文件时默认展示全文状态。

## 设计说明

- **默认路径最简单。** 用户打开侧栏后只需要确认模型和额外要求，主按钮按整篇文档生成；没有“整篇文档 / 选中内容”这种本不该由用户承担的选择。
- **选择动作本身就是触发器。** 用户在文档中选中文字后，侧栏标题自然切换为“根据选中内容整理思维导图”，并在模型卡片上方显示选区原文。用户不需要在侧栏确认范围。
- **原文必须可见，但不挤占操作区。** 选区内容放在模型配置之前，使用固定高度、只读的文本区；短文字不额外留白，长文字在文本区内滚动，不让整个侧栏反复改变高度。
- **没有长短状态分支。** 不再区分短选区和长选区，也不做折叠按钮；用户看到的是同一个组件和操作方式。
- **一次性语义。** 点击生成后清除选区上下文，下一次回到整篇文档；避免旧选区在后续生成中悄悄持续生效。
- **保持侧栏安静。** 默认状态没有任何选区文案，模型配置和生成按钮构成唯一的视觉重心。

## 原型到实现的映射

现有实现可从 `src/renderer/src/components/workbench/WorkbenchMindmapPanel.tsx` 已有的 `pendingSelection` 派生状态：

- 有 `pendingSelection` 时，面板始终显示固定高度的只读选区文本；`materialProvider` 直接发送 `pendingSelection.text`。
- 没有 `pendingSelection` 时，按现有逻辑发送全文，界面不出现任何范围相关文字。
- 生成完成后调用 `setPendingSelection(null)`，下一次生成自然回到全文。
- 选区预览标题栏提供“清除”操作，可一键回到整篇文档生成；切换文档时继续沿用现有清除逻辑。生成任务进入完成、失败或取消终态后，也会自动清除一次性选区。
- 蓝色正文标记继续由文档中的原生选区承担；侧栏展示同一段文字，供用户确认实际生成内容。

该方案已落到 `ConversationMindmapPanel` 与 `WorkbenchMindmapPanel`：选区预览作为通用插槽注入面板，工作台文档来源传入预览内容与清除回调。

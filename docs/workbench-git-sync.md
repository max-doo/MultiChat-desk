# 工作台版本管理与大文件策略

## 1. 能力范围

工作台的版本管理直接调用系统 Git，不随应用打包 Git 库，也不保存任何账号凭据。它只管理当前工作区：当工作区是某个仓库的子目录时，状态、暂存和提交都不会带到仓库的其他目录。

| 操作 | 行为 |
|---|---|
| 初始化仓库 | 仅在用户确认后执行 `git init`；没有 `.gitignore` 时补一份常规忽略项 |
| 提交 | 提交标题默认使用 `YYYY-MM-DD HH:mm`；仓库首次提交默认 `Initial commit`；两者都可改写；提交前先落盘当前编辑内容 |
| 拉取 | 只允许快进；已跟踪文件有未提交改动时先引导提交；未跟踪文件不阻止拉取，若与远程同名则由 Git 拒绝并提示；工作区是仓库子目录时先确认，因为会同步整个仓库 |
| 合并 | 本地和远程都有新提交时，由用户确认后显式合并；冲突自动撤销并回到操作前 |
| 推送 | 先 fetch 校准远程状态；没有上游分支时先确认，再用 `push -u <remote> HEAD` 建立跟踪关系（优先 origin，没有则用已有远程） |
| 移动文件 | 磁盘移动完成后，把原 blob 写入新路径的索引条目，Git 识别为重命名而不是删除加新增 |

远程地址在“工作区设置”中填写，只写入仓库的 `.git/config`。HTTPS 凭据由系统 Git 凭据管理器保存；应用不回显带凭据的完整地址，也不会把脱敏后的 `***` 写回仓库。已有 `origin` 时沿用 `origin`，没有时沿用仓库已有的第一个远程名。

## 2. 文件移动与 Git 历史

Git 不存储“重命名”这个动作，只在比较两个提交时根据内容相似度推断。文件已经提交过、随后在工作台中移动时，应用会把原索引条目的 blob 直接搬到新路径，因此暂存区里就是重命名记录，历史连续。

文件夹移动会逐个映射目录内所有已跟踪文件，而不是只记录目录本身。未跟踪文件、被忽略文件，以及位于未跟踪目录中的文件不会进入暂存区；如果 Git 未安装或当前目录不是仓库，移动仍正常完成，只是不做版本记录。

变基或合并进行中不写索引，避免破坏 Git 的可恢复状态。

## 3. 单文件体积限制

Git 本身没有单文件硬限制，限制主要来自托管平台和网络传输。

| 平台 | 限制 |
|---|---|
| GitHub | 单文件超过 50 MiB 警告，超过 100 MiB 拒绝；单次 push 上限 2 GiB；建议仓库小于 1 GB，5 GB 以内较稳妥 |
| GitLab.com | 单次 push 上限 5 GiB；仓库（含 LFS）免费版上限 10 GiB，付费版更高；自建实例可配置 |
| Azure DevOps | 默认建议单文件不超过 100 MB，可用策略强制限制 |

业界常见处理方式是按文件性质分流：

- 压缩包、安装包、视频、设计源文件、构建产物：写入 `.gitignore`，不进入仓库。
- 需要版本控制的大二进制：使用 Git LFS，仓库只存指针。
- 超大文件：放对象存储或网盘，仓库中只保存链接或说明。
- 服务端兜底：用 push rule、仓库策略或 CI 大文件检查阻止误提交。

本应用不自动启用 Git LFS：LFS 需要额外安装、配置远端存储并可能产生流量费用，自动开启会让普通知识库在无感知的情况下依赖外部服务。应用采用“50 MB 提示 + 用户确认 + 忽略模板”的方式，把选择权留给用户。提交接口本身也会拒绝未确认的大文件，避免只靠界面提示被绕过。

## 4. 忽略规则

创建工作区时，只有空目录会写入默认 `.gitignore`；已有内容的目录不擅自新增文件。初始化 Git 仓库时，也只在没有 `.gitignore` 的情况下补默认规则。

默认忽略项只包含几乎不会与知识库正文冲突的通用项：系统临时文件、Node 依赖、Python 依赖与缓存、编辑器交换文件与本地历史，以及下面列出的应用与 Obsidian 生成物。压缩包、PDF 与办公文档、视频、设计源文件、安装包、构建产物、`.idea/` 与 `.vscode/` 默认不忽略：知识库里也可能把它们当作正文附件，或需要把编辑器配置随仓库同步。

工作区内的应用与 Obsidian 数据按“配置保留、生成物忽略”处理，不整目录忽略：

- `.multichat/` 只忽略 `image/`、`results/`、`cache/`、`logs/` 这些可再生成的产物；索引、导图和其他配置会正常进入版本控制。
- `.obsidian/` 只忽略 `workspace.json`、`workspace-mobile.json`、`cache/` 这类设备本地状态；主题、插件、快捷键等配置会随仓库同步。

`build/`、`dist/`、`coverage/` 这类通用目录名不放进默认规则，因为知识库里也可能有同名笔记目录；需要时在设置中勾选「构建与测试产物」。

工作区设置中可以：

- 查看当前规则并删除；
- 手动添加规则；
- 按文件类型勾选要忽略的组：系统临时文件、压缩包、安装包、PDF 与办公文档、视频、设计源文件、Node 依赖、Python 依赖与缓存、构建与测试产物、编辑器临时文件、IDE 配置、应用生成物、Obsidian 本地状态；
- 勾选一个组会补入该组缺失的规则；取消勾选只移除该组规则，其他组和手写规则不受影响；
- 组内规则被手动删掉任意一条时，该组会自动回到未勾选状态，避免显示与文件内容不一致；
- 针对超过 50 MB 的未跟踪文件，直接按扩展名添加忽略规则。

保存采用行级差异：只删除被移除的规则行，在文件末尾追加新规则，保留用户已有注释和空行。若 `.gitignore` 在设置打开后被其他程序修改，保存前会提示确认，不会静默覆盖。

## 5. 出错时的边界

- 没有安装 Git：界面提示不可用，文件移动降级为普通移动，不影响本地文件。
- 没有配置用户名或邮箱：提交失败并提示先在系统 Git 中配置。
- 远程认证失败：提示检查系统 Git 凭据，不弹出凭据输入框。
- 远程已有新提交：拒绝推送并提示先拉取。
- 合并冲突：自动执行 `merge --abort`，保留操作前的本地内容。
- 工作区是仓库子目录：提交仍只包含工作区范围；拉取/合并会更新整个仓库，执行前单独确认。
- 未跟踪的大文件：提交前明确提示，用户可以选择取消并去设置忽略；确认后才把 `allowLargeFiles` 传给主进程。

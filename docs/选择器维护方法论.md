# 选择器维护方法论（messageContainer + researchMode）

> Created: 2026-07-02 22:03 (CST, UTC+8)
> Updated: 2026-07-03 00:18 (CST, UTC+8) — v2 独立窗口 + researchMode 探针

## 铁律

1. **探针逻辑必须与 `src/shared/utils/webviewScripts.ts` 同源**。
   - messageContainer 探针：`src/renderer/src/utils/selectorDiagnostics.ts` 的 `safeQueryAll`/shadow 兜底/去重/`isVisible` 拷贝自 `webviewScripts.ts:1509-1572`。
   - researchMode 探针：`buildResearchProbeScript` 的 `findElement`/`matchText`/`findMenuOpener` 拷贝自 `webviewScripts.ts:640-781`（含 `exclude` 排除逻辑，区分 Search/Research 的关键）。
   - 改 `webviewScripts.ts` 的匹配逻辑时必须同步两处探针，否则"探针命中 ≠ 生产命中"。探针为**只读复刻**（不点击、不 `normalizeClickable`）。
2. **严格脱敏**：探针报告只含元素元数据（tag/className/id/data-testid）+ 可见正文长度，**不含正文内容 / outerHTML / aria-label 值 / 其他属性值**，避免泄露模型输出与用户输入。
3. **仅 dev 可见**：诊断入口（设置抽屉 🔬 按钮）经 `import.meta.env.DEV` 门控，production build 不含（已用 `grep -c "选择器诊断" out/renderer/assets/index-*.js` = 0 验证）。独立诊断窗口仅由该 dev 按钮经 `openDiagnosticsWindow()` 触发，prod 无 UI 入口。

## 闭环

### messageContainer 闭环

1. 开 dev（`npm run dev`），主窗口打开目标平台卡片，发一条一次性 prompt，**等回复流式结束**。
2. 设置抽屉 → 点 🔬「选择器诊断 (dev)」→ 弹出**独立诊断窗口**（不覆盖主窗口，可并行操作）。
3. 诊断窗口 Tab1「消息容器」→ 左侧选平台 → 点「诊断 messageContainer」。
4. 读候选表格：
   - ✅ 全部命中：首位候选 visibleHitCount>0 且正文长>0，无需动。
   - ⚠️ 命中空元素：有 visibleHitCount>0 但正文长=0，说明命中了占位/空容器，需重排或删除该候选。
   - ❌ 全失效：所有候选 visibleHitCount=0，需补新选择器。
   - ⚫ 未加载：该平台不在主窗口当前阵容，store 中无其 webview ref（响应 `{ ok:false, error:'平台未加载' }`）。
5. 补新选择器时**优先稳定信号**（优先级从高到低）：
   1. `data-testid` 精确属性
   2. `aria-label` 精确
   3. `role` + 语义
   4. 语义类名片段（如 `[class*="markdown"]`）
   5. 结构定位（如 `form button[type="submit"]`）

   **避开哈希类名**（如 `tagBtn-OADWVI`、`selected-OsA38F`），这是改版重灾区。元素指纹列直接给出可复制的 tag.className#id [data-testid=...]。
6. 改 `src/shared/config/selectors.ts` 对应平台的 `messageContainer`，**bump `version`**（如 13→14），重启 dev。
7. 再点诊断确认新候选 visibleHitCount>0 且正文长>0。

### researchMode 闭环（深度研究按钮）

1. 主窗口打开目标平台，**建议在新对话页**（实跑会真实点击页面，可能污染当前对话）。
2. 设置抽屉 → 🔬 → 独立诊断窗口 → Tab2「深度研究」→ 选平台。
3. 先点「只读探测 steps」：对 `researchMode.steps` 每步报 `found`/`matchedVia`（selector / semantic-fallback / menu-opener-fallback）/元素指纹。
   - ✅ 关键步（开菜单 + 选 Deep Research 项）found=true：链路通。
   - ❌ 某步 found=false：该步 selector 或 text/regex 失效，用元素指纹撰新 selector。
   - 注意 `exclude` 步：若误命中 Search 项，说明 exclude 正则没拦住，需收紧 exclude。
4. 失效步用指纹撰新 selector/regex/exclude → 改 `selectors.ts` 对应平台 `researchMode.steps` → bump `version` → 重启 → 再探。
5. **「实跑 enableDeepResearch」按钮**：真实点击页面触发 Deep Research 开启（经主窗口 `webviewRefs.get(id).enableDeepResearch()`）。仅当只读探测全通、且确认在合适对话页时点，观察菜单是否弹出/选项是否被选中。⚠️ 该按钮真实改页面状态，不止查看。

## 跨窗口 IPC 链路（出问题时排查方向）

诊断窗口不持有平台 webview（webview 在主窗口），故经主进程中转：
`诊断窗口 diagnosticsProbe(modelId,type)` → 主进程 `diagnostics:probe` → 主窗口 `onDiagnosticsProbeRequest` → `webviewRefs.get(id).probeMessageContainer/probeResearchMode` → `diagnosticsProbeResponse` 回传。
- 主窗口 5s（probe）/15s（run-research）未响应 → 主进程超时兜底回 `{ ok:false, error:'主窗口响应超时' }`。
- channel 名：`diagnostics:open-window` / `probe` / `probe-request` / `probe-response` / `run-research` / `run-research-request` / `run-research-response`。

## 成本

探针让诊断变 2 秒检查，单平台成本主要由"触发一次回复"决定。14 平台 messageContainer 约半小时；researchMode 因需新对话页 + 实跑验证，单平台约 2-3 分钟。

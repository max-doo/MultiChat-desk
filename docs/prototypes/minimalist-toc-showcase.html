SPECIFICATION DRAFT

MultiChat Desk 极简 Markdown 原位大纲导航

实现“静止时仅有轻柔横线、悬停时横线原位变形展开为小节标题、周围未激活横线平滑避让、外层容器完全无边框透明”的高品质沉浸式导航。

01 设计目标与交互动机

在传统桌面文档或 IDE 中，侧边大纲往往需要占据 200px~260px 的固定宽度。当用户在 MultiChat Desk 中同时打开右侧 AI 助手进行文献提炼或对比辩论时，主编辑区宽度会缩窄到 600px 左右。此时常驻的大纲栏将严重挤占正文，破坏排版。

核心设计准则： 保持导航容器 100% 透明与零边框；只在鼠标主动交互时提供精准的信息反馈，平常状态下不打破正文阅读的注意力心流。

02 横线原位变形技术原理

所谓“横线原位变成标题”，本质上是把常规的“外部独立 Tooltip 浮动”转变为“同一 DOM 节点的尺寸与透明度弹簧演变”。

2.1 层级线长编码算法

静态横线不仅是一根线，它通过物理尺寸对标题层级进行了直观映射： H1: 26px、 H2: 18px、 H3: 12px。用户只需通过余光就能感知整篇文档的结构层次。

2.2 标题展开时的微过渡机制

当指针移入具体的某根线段时，该线段从右向左平滑展开，小横线缩短为前缀圆点（Bullet Dot），标题文字在 200ms 内完成透明度与位移的平滑淡入，完全消除传统 Tooltip 带来的视觉割裂。

03 周围横线的动态调整机制

当某一个小节横线膨胀展开为 28px 高度的文字徽章时，如果周围横线静止不动，文字会遮挡上下的小横线。因此，整个导航轨需要具备物理避让与焦点聚焦能力。

3.1 物理风琴避让（Accordion Push）

当激活项高度伸展时，利用 CSS Grid 或弹性盒的平滑插值，把上方的线段向上微移、下方的线段向下顶开。这种方式具有极强的物理反馈感。

3.2 弹性防抖微波（Elastic Debounce - 推荐）

为了解决鼠标高速滑动时可能发生的“目标在指针下跳跃脱靶（Hunting Jitter）”，在弹性模式中，所有槽位预留温和的基础高度，仅对紧邻的上下条目施加轻度位移与透明度虚化，操作稳定性更高。

04 透明容器的边界处理与分屏适配

整个导航容器摒弃一切背景卡片、描边、外阴影。它以绝对定位沉浸地附着在主画面的右侧预留边缘，甚至当用户打开右侧 AI 助手时，也完全不破坏分屏界面的整洁度。

4.1 滚动监听（ScrollSpy）精准锚定

阅读过程中，页面顶部 120px 黄金阅读线下的当前章节横线会自动点亮为主题高亮蓝（#3b82f6），让用户无需悬停即可随时掌握阅读进度。

05 落地结论与工程实施

该方案成功兼顾了“极度纯粹的视觉美学”与“随取随用的信息可达性”，建议封装为独立的 React 轻量组件 WorkbenchMinimalToc.tsx，直接集成到工作台的富文本与源码视图中。

分屏宽度抗压测试

当侧边栏展开后，中间编辑区的宽度被压缩。请移动鼠标到右侧的导航横线上试一试：

  • 无边框透明容器：没有任何多余边框切割视野，丝滑融入正文；
  • 横线原位变形：鼠标移到某根线，该线原地展开为标题，其他线被平滑推开避让；
  • 点击任意小节，精准平滑滚动并产生柔和蓝光聚焦脉冲。
